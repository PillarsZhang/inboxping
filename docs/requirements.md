# InboxPing 产品需求（MVP）

## 目标

在 ARM64 树莓派上通过 Docker Compose 长期运行，同时监听多个邮箱。新邮件到达后尽快只读获取，经可替换 AI 服务完成中文摘要、重要度、行动项及广告/钓鱼/恶意风险判断，将值得关注的邮件推送到企业微信，并在 Web 页面展示运行情况。

## 功能范围

- 多账户隔离监听，每个账户显式选择 IMAP IDLE、持久 IMAP 轮询或 POP3 轮询；协议内自动重连，但不进行不透明的跨协议降级。
- 以只读模式打开邮箱，使用 `BODY.PEEK[]` 拉取，绝不移动、删除、回复或设置已读。
- 使用 `账户 + 文件夹 + UIDVALIDITY + UID` 幂等入库，Message-ID 辅助去重。
- 解析文本/HTML、多语言编码和附件元数据；默认不上传附件内容。
- AI 服务通过 OpenAI-compatible Chat Completions API 配置，不绑定厂商。
- AI 输出固定结构：概括标题、中文摘要、分类、重要性分、风险分、行动项、截止日期、是否推送与推送理由。
- 大量收件人的邮件保留完整本地名单，列表展示和 AI 输入只使用有界概况；详情页按需展开并支持复制纯地址。
- 记录模型服务实际返回的分析与翻译输入、输出 Token 用量；未提供时不估算。
- 邮件详情支持按需流式翻译全文并实时显示，完整结束后才缓存结果，允许用户明确重新翻译。
- 原文和翻译可分别导出带结构化 YAML Front Matter 的 Markdown；原始 EML 按需从原邮箱只读获取并直接下载，不在本地持久化。
- 发件认证信息作为 AI 判断的参考，程序直接采用 AI 的推送决定；AI 分析失败时仅入库待重试，不自动推送。
- Prompt 要求 AI 不推送高风险、疑似钓鱼、病毒和恶意邮件；重要性与风险分数不触发额外程序规则。
- 支持企业微信自建应用消息和群机器人 Webhook；按命名通道独立记录投递结果。
- Web 页面展示状态、邮件、分析和最近事件，支持手动重分析、重推送。
- CLI 支持诊断、账户检查、Prompt 预览、单封重分析和批量重处理。
- SQLite WAL 持久化，数据默认永久保留，结构化 Loguru 日志输出 stdout。

## 非功能要求

- Python 3.12，使用 uv 管理依赖和命令。
- 构建 `linux/arm64`/`linux/amd64` 均可运行的镜像。
- 单邮箱故障不影响其他邮箱；重启后从持久化游标继续。
- 配置集中存放在 `config.yaml`，密码、API Key、应用 Secret、Webhook 使用 SecretStr 校验，页面与日志不回显。
- 默认不公开监听到公网；管理页面提供会话认证。

## 暂不包含

- 回复、发送、移动或删除原邮箱邮件。
- 附件内容分析、完整邮件客户端、多用户权限与移动 App。
- OAuth 邮箱认证，以及企业微信之外的通知适配器。

## 验收标准

1. 两个账户可同时监听，断线重连后不漏掉期间邮件且不重复通知。
2. 邮件在原邮箱中保持未读状态；IMAP 使用只读文件夹和 `BODY.PEEK[]`，POP3 使用 UIDL/RETR 且不发送 DELE；一个账户只配置一种协议。
3. AI 输出异常、超时或不可用时，邮件仍落库并留下可重试状态。
4. AI 决定推送的邮件每通道仅发送一次；失败可自动或手动重试。
5. Web 可查看账户健康、最近邮件与错误，CLI 可完成诊断和 Prompt 迭代。
